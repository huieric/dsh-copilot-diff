# Copilot review and checkpoints

Build on dsh-copilot-diff 0.1.13. Match VS Code Copilot Chat's compact dark/light theme-aware conversation file changes: changed-file list with green/red counts, Keep/Undo, click a file or count to open the existing right sidebar review pane focused on that turn and file. Provide unified and side-by-side diff modes, keyboard access, file navigation and visible action errors.

Capture actual local workspace file content before and after shell tools (bash, exec, exec_command, execute_command, replace variants, Python scripts); do not infer writes solely from command text. Support git repositories (dirty tracked and untracked), nested repositories and bounded non-git directories. Do not scan a whole home recursively or include dependency/cache/.git/secret stores. Limits must be explicit and incomplete snapshots must never claim complete restore coverage. Preserve file creation, deletion, empty files, trailing newlines. Record writes even when a command exits unsuccessfully after writing. Existing editor tool records remain available.

Create a persistent checkpoint before each turn's first tool executes, preferably at turn/start when lifecycle awaits permit. Restore to the chosen turn's starting file state, including reversing later recorded turns. Keep does not delete checkpoint data. Restore touches captured changed files only, preflights all paths for conflicts against latest recorded contents and refuses before writing if a file has unrelated later edits. Respect host fs write policy, do not follow symlinks outside root, do not reset git/index/refs, do not rewrite conversation history. Running turns cannot be restored. Persisted snapshots must survive restart. Historical turns without reliable snapshots display unavailable, never fabricate restore capability. Excluded binary/oversized files must be reported and not silently overwritten.

Testing: real temporary workspaces with sed and Python replace/create/delete, shell failure after write, multiple turns and keep then checkpoint restore, conflict refusal without partial modification, restart persistence, symlink and scope exclusions. Client tests verify file click opens review, turn scoping, checkpoint control, diff mode/navigation. Verify UI through existing DSH GUI at http://127.0.0.1:3080 when possible; synthetic component fixtures must be labelled as such.
