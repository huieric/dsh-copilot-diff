## Decisions

- The finished line states the step count because the host publishes `messageCount`, `toolCallCount` and `subagentCount` on the node but no step field; the count is read from `turn.steps.length`, the same array the host's own `lastStep` helper reads. A single step uses the singular key `turn.completedOne`, and a turn whose steps cannot be read falls back to the old `Completed in {duration}` text.
- The chevron is a separate `ld-processchev` button placed after the totals, `opacity: 0` until `.ld-processhead:hover` or `:focus-within`, with `tabIndex: -1` so the keyboard path stays on the label. Ordering it after the totals is what makes the line read `已完成 16 步，用时 19分42秒 +32 −32` instead of ending on a control glyph.
- File rows keep the host's own markup, so their `+A −R` is coloured by a stylesheet rule rather than a re-render: `[class*="diffAdded"]` and `[class*="diffRemoved"]` with `!important` beat the host's `[aria-expanded=true]` and `:hover` rules, and matching the semantic half of the hashed class name survives a host rebuild.

- The click is delegated from one capture-phase listener on `document` instead of shadowing the host row with our own `tool.call.toolview` entry at `priority: -1`. Shadowing would replace a row the user already accepted (title, size, chevron, expansion behaviour all reimplemented) just to make two numbers clickable; delegation changes nothing visually, and it keeps working as long as the totals stay inside `[class*="diffStat"]` and the row keeps `data-chat-call-id`.
- The review pane is one flat column instead of a file index plus a single-file editor, because that is what the user pointed at: Copilot's `Response File Changes` lists every file's diff one after another, and an index makes the reader pick a file before seeing anything. The per-file scroller had to go with it — a nested `overflow:auto` inside the column would trap the wheel per file — so `DiffBody` gained `inline` (no `ld-vscroll`, bodies grow in flow), `expandAll` and `ld-gap` stayed the mechanism for untouched runs, and each inline body caps at 240 rows with its own `Show N more lines` so a 1200-line file cannot dominate the column. Switching unified/split still drives every section at once.
- The checkpoint moved to a boundary row under the turn card and gained a fork beside it: at the turn header it read as part of the `Completed …` line, while the reference puts it between two turns, where it acts on the turn that just ended. Fork reuses the host's own `sessions.fork({sessionId, atSeq, increaseTitle:true})` with `props.seq` (the turnTail slot already publishes the turn-end sequence) and then `uiWorkspace.openSession(childId)`, so no new RPC and no copied fork seed; the button disables itself and says why when `sessions.fork` is absent. The boundary row renders even for a turn that changed no files, because restoring a checkpoint and forking are still meaningful there.
- The turn footer is now a card, not a chip row: it reuses the geometry of `dsh-file-review`'s ProducedFiles card (12 px radius, 30 px icon tile, 56 px header, 38 px divider-separated rows, 13 px text, `已编辑 N 个文件 +A −R`) instead of inventing a second look for the same information. Clicking the title, **审查**, or any row opens the Changes pane, and a row click still scopes it to that file.
- *(0.8.3 supersedes this: the card is gone, and the same **保留** / **撤销** now live only in the review pane's header and its per-file rows.)* **保留** stays, as a quiet text button beside **撤销** and the bordered **审查**. `dsh-file-review` has no Keep action, but this plugin does (`turn.keepTitle`: keep the edits and stop tracking them), and dropping the button would silently remove functionality. The three actions live in one `.ld-turnactions` group with `margin-left: auto`, so a narrow chat column wraps them as a unit to a right-aligned second row instead of orphaning **审查** on the left.
- *(0.8.3 supersedes this: the plugin renders no card of its own, so `TURN_CARD_ROWS` no longer exists.)* The card lists six files and folds the rest behind `另有 N 个文件` (`TURN_CARD_ROWS = 6`), matching `dsh-file-review`'s `SHOWN_LIMIT`; expansion is local `useState`, and the button disappears once expanded.
- Per-file status pills (`新增 / 修改 / 删除`) and the per-row `查看修改` link are gone: the row itself is the affordance, and the status still shows in the pane and on the inline call rows.
- The Changes pane's file index stays a single folded `› 文件 N · current file +A −R` header by default; opening it shows the list, and choosing a file folds it again so the diff keeps the height.
- The chat no longer builds its own list of edits. `turn-process` is only the "Completed in …" fold header plus `+A −R` and Restore Checkpoint; reasoning, commands and edit rows stay in the host's original order, and each file tool's diff renders through the keyed `tool.call.toolview` slot on that call. This is what makes "think → command → edit" interleave instead of collapsing into one summary.
- Shell-driven edits (`sed`, `python -c`, scripts) have no per-command attribution in the host's workspace event, so with the guard off they appear only in the turn footer's file list. File tools (`edit` / `write` / `apply_patch` / `str_replace_editor`) get an inline diff at their call.
- The write guard runs in `tools/pre-execute` and denies `sed -i`, `perl -i`, writing Python heredocs/`-c`, `tee`/redirection, `dd`, `truncate`, `git apply|checkout|restore|reset --hard|clean -f`, and `patch` when their targets are not disposable. Build/cache directories, `/tmp`, `/var/tmp` and `/dev/null` stay writable; `DSH_COPILOT_DIFF_GUARD=off` disables the guard. This is a heuristic against accidental shell edits, not a sandbox: dynamically constructed commands can bypass it. Denials return the tool error text to the model, which is expected to retry with a recorded file tool.
- Inline diffs start collapsed, matching Copilot's step rows; clicking the row (or chevron) expands the whole-file context with `⋯ N unchanged lines` gaps that open on demand.
- The whole-file view is reconstructed from bounded before/after snapshots plus hunk coordinates. Historical records without a snapshot fall back to hunk rendering and say so. `file-text` remains a read-only RPC over persisted records and applies the same visibility filter; the client no longer calls it after removing the turn list.
- Large diffs are windowed at a fixed 22 px row height (enabled above 240 rows), with the row model cached by `(before, after, hunks)` identity and scroll updates coalesced per animation frame. `1 of N` navigation goes through `navRef`, which sets `scrollTop` before scrolling the target into view, so a folded or off-screen hunk still resolves.
- Unchanged regions fold into a clickable `⋯ N unchanged lines` row; this gives full-file context without dumping an entire file into the chat.
- Mark as Reviewed advances to the next unreviewed file and the pane header shows `reviewed/total`, mirroring the VS Code review pass.
- Restore Checkpoint stays a separate confirmed action from per-file and per-turn Undo; Keep preserves checkpoints. Conversation history is not rewritten, and the UI says so.

## 0.8.2 — sidebar diff totals coloured

Root cause: `--ld-add` / `--ld-del` are declared only on `.ld-pane, .ld-diff, .ld-turn, .ld-process, .ld-row`. The sidebar session-row badge (`sidebar.workspaces.session.row.action` → `SessionRowBadge`) and its hover card (`sidebar.session.row.hover` → `SessionRowHover`) render outside every one of those containers, so `color: var(--ld-add)` had no value, became invalid at computed-value time, and the `+A −R` inherited the label colour — grey.

`output/verify/sidebar-colors.mjs` (CDP 9333, fixture at 1400×900) reads both sides of the fix:

- before: `.ld-sidebadge .ld-add` = `rgb(0, 0, 0)` (invalid variable, inherited), `--ld-add` on the badge = `""`, while `.ld-turnstats .ld-add` inside the card was already `rgb(74, 222, 128)`;
- after: badge `rgb(74, 222, 128)` / `rgb(248, 113, 113)`, hover card `rgb(74, 222, 128)` / `rgb(248, 113, 113)` (`4 个文件已修改 · 4 次编辑 · +13 −4`), and `--ld-add` resolves to `#4ade80` on the badge itself.

Fix: the two utility classes carry `var(--ld-add, var(--dsw-alias-state-success-primary, #3fb950))` (error pair symmetrical), and `.ld-sidebadge, .ld-sidehover` declare both variables themselves so nested children inherit them.

## 0.8.3 — the plugin would not load, one card per turn, boundary row below the icons

### Root cause of `Failed to load plugins`

The client `apply()` threw on its first keyed registration and the fiber went `failed`, so the boot overlay replaced the whole app. The message, captured by instrumenting `apply()` in the installed copy:

```
Error: keyed slot "tool.call.toolview" already has an entry for key "edit"
at priority 0 (registered by file-mutation-toolview)
— register at a different priority to shadow it (lowest renders)
```

The renderer's keyed branch rejects a second entry with the same `key` **and** the same `priority`. The host's `file-mutation-toolview` already held `edit` / `write` / `apply_patch` / … at the default `0`, and this plugin meant to *replace* those rows but registered at the default too. A second collision followed on `conversation.chat.node` key `turn-process` (held by the host's `tk`). Both now register at `priority: -1`, the documented way to shadow, since lowest renders.

Verification note for next time: `curl` cannot see this. The overlay is rendered by the front-end runtime, so "the server answers 200 and the plugin is in the manifest" says nothing about whether `apply()` succeeded — check the overlay node or the fiber state in a real browser.

### One card per turn

The host already renders a changed-files card on `conversation.chat.turnTail` (`@deepseek-ai/dsh-client-ui-deliverables`, title `已编辑 {count} 个文件`). This plugin rendered its own card on the same slot with a similar title, so a turn showed two cards with different numbers — the host's counts the host's changes state, the plugin's counted its own per-call records. A plugin cannot unregister a core entry, and hiding it with CSS would be a hack, so the plugin stopped rendering its card: `TurnFooter`, `TURN_CARD_ROWS`, `CardFileGlyph`, `CardReviewGlyph`, the ten `turn.*` card keys and every card CSS rule are gone. **保留** / **撤销** stay in the review pane, still reached from the completed line's `+A −R` badge and from each tool row's numbers.

### Boundary row below the icon line

`TurnTailNodeView` renders `children: [tail, MessageIconActions]` inside one flex column (`TS9iAW_root`), so the copy/usage icon line is the column's **last** child whatever `order` a slot entry registers at — the checkpoint row therefore always landed between the card and `Turn cost`. The row now carries its own `order: 1`, placing it after that line. Visual order only: focus and screen-reader order still follow the DOM.
