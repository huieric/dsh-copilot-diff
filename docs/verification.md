## Decisions

- The turn footer is now a card, not a chip row: it reuses the geometry of `dsh-file-review`'s ProducedFiles card (12 px radius, 30 px icon tile, 56 px header, 38 px divider-separated rows, 13 px text, `已编辑 N 个文件 +A −R`) instead of inventing a second look for the same information. Clicking the title, **审查**, or any row opens the Changes pane, and a row click still scopes it to that file.
- **保留** stays, as a quiet text button beside **撤销** and the bordered **审查**. `dsh-file-review` has no Keep action, but this plugin does (`turn.keepTitle`: keep the edits and stop tracking them), and dropping the button would silently remove functionality. The three actions live in one `.ld-turnactions` group with `margin-left: auto`, so a narrow chat column wraps them as a unit to a right-aligned second row instead of orphaning **审查** on the left.
- The card lists six files and folds the rest behind `另有 N 个文件` (`TURN_CARD_ROWS = 6`), matching `dsh-file-review`'s `SHOWN_LIMIT`; expansion is local `useState`, and the button disappears once expanded.
- Per-file status pills (`新增 / 修改 / 删除`) and the per-row `查看修改` link are gone: the row itself is the affordance, and the status still shows in the pane and on the inline call rows.
- The Changes pane's file index stays a single folded `› 文件 N · current file +A −R` header by default; opening it shows the list, and choosing a file folds it again so the diff keeps the height.
- The chat no longer builds its own list of edits. `turn-process` is only the "Completed in …" fold header plus `+A −R` and Restore Checkpoint; reasoning, commands and edit rows stay in the host's original order, and each file tool's diff renders through the keyed `tool.call.toolview` slot on that call. This is what makes "think → command → edit" interleave instead of collapsing into one summary.
- Shell-driven edits (`sed`, `python -c`, scripts) have no per-command attribution in the host's workspace event, so with the guard off they appear only in the turn footer's file list. File tools (`edit` / `write` / `apply_patch` / `str_replace_editor`) get an inline diff at their call.
- The write guard runs in `tools/pre-execute` and denies `sed -i`, `perl -i`, writing Python heredocs/`-c`, `tee`/redirection, `dd`, `truncate`, `git apply|checkout|restore|reset --hard|clean -f`, and `patch` when their targets are not disposable. Build/cache directories, `/tmp`, `/var/tmp` and `/dev/null` stay writable; `DSH_COPILOT_DIFF_GUARD=off` disables the guard. This is a heuristic against accidental shell edits, not a sandbox: dynamically constructed commands can bypass it. Denials return the tool error text to the model, which is expected to retry with a recorded file tool.
- Inline diffs start collapsed, matching Copilot's step rows; clicking the row (or chevron) expands the whole-file context with `⋯ N unchanged lines` gaps that open on demand.
- The whole-file view is reconstructed from bounded before/after snapshots plus hunk coordinates. Historical records without a snapshot fall back to hunk rendering and say so. `file-text` remains a read-only RPC over persisted records and applies the same visibility filter; the client no longer calls it after removing the turn list.
- Large diffs are windowed at a fixed 22 px row height (enabled above 240 rows), with the row model cached by `(before, after, hunks)` identity and scroll updates coalesced per animation frame. `1 of N` navigation goes through `navRef`, which sets `scrollTop` before scrolling the target into view, so a folded or off-screen hunk still resolves.
- Unchanged regions fold into a clickable `⋯ N unchanged lines` row; this gives full-file context without dumping an entire file into the chat.
- Mark as Reviewed advances to the next unreviewed file and the pane header shows `reviewed/total`, mirroring the VS Code review pass.
- Restore Checkpoint stays a separate confirmed action from per-file and per-turn Undo; Keep preserves checkpoints. Conversation history is not rewritten, and the UI says so.
